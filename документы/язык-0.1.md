# 1. Назначение языка

«Улитка» — русский язык программирования,
создаваемый для разработки программ,
системных инструментов, веб-приложений
и в дальнейшем собственной операционной системы.

Главная цель языка — дать возможность человеку
писать программы на русском языке.

Язык должен быть:

- понятным человеку;
- последовательным;
- предсказуемым;
- расширяемым;
- пригодным для создания больших программ;
- пригодным для дальнейшего создания собственной ОС;
- пригодным для создания русской веб-среды.

# 4. Официальный словарь языка

## 4.1 Управление программой

программа — объявляет программу.
начало — обозначает начало выполняемой части программы.
конец — завершает текущий блок.

## 4.2 Вывод и ввод

показать — выводит информацию.
ввести — получает информацию от пользователя.
в — указывает переменную, в которую сохраняется введённое значение.

## 4.3 Переменные

пусть — создаёт новую переменную.

## 4.4 Условия

если — начинает условную конструкцию.
тогда — обозначает начало выполняемой части условия.
иначе — задаёт альтернативную ветку.

## 4.5 Циклы

пока — выполняет блок, пока условие истинно.
повторить — задаёт повторение определённое количество раз.
раз — указывает количество повторений.

## 4.6 Функции

функция — объявляет функцию.
вернуть — возвращает значение из функции.

## 4.7 Логические значения

истина — логическое значение «да».
ложь — логическое значение «нет».

## 4.8 Логические операции

и — логическое И.
или — логическое ИЛИ.
не — логическое отрицание.

# 7. Типы данных

## 7.1 Число

Тип «число» хранит целые и дробные числа.

Примеры:

30
-15
20.5
19.99

Десятичный разделитель — точка.

## 7.2 Текст

Текст записывается в двойных кавычках.

Примеры:

"Привет"
"Владимир"
"Привет, мир!"
""

## 7.3 Логическое значение

Логический тип имеет два значения:

истина
ложь

## 7.4 Список

Список хранит несколько значений.

Пример:

["Владимир", "Анна", "Иван"]

Индекс первого элемента равен 0.

## 7.5 Пустое значение

Специальное значение:

пусто

Оно означает отсутствие значения.

## 7.6 Символ

Отдельного типа «символ» в версии 0.1 нет.

Он может быть добавлен в будущих версиях.

# 11. Специальные символы текста

\n — новая строка.
\t — табуляция.
\" — кавычка внутри текста.
\\ — обратная косая черта.

# 12. Числа

Разрешены целые и дробные числа.

Десятичный разделитель — точка.

Примеры:

10
-10
20.5
-3.14

# 13. Скобки

Скобки используются для изменения порядка вычислений.

Пример:

пусть результат = (10 + 20) * 2

# 14. Приоритет арифметических операций

1. Скобки.
2. Умножение, деление и остаток.

# 15. Списки

Список создаётся с помощью квадратных скобок.

Пример:

пусть имена = ["Владимир", "Анна", "Иван"]

Индексация начинается с 0.

Получение элемента:

имена[0]

Изменение элемента:

имена[1] = "Мария"

Пустой список:

[]

# 16. Операции со списками

Добавление:

добавить "Пётр" в имена

Удаление:

удалить имена[1]

Получение длины:

длина(имена)

# 17. Ошибки индекса

Если индекс выходит за пределы списка,
программа должна получить понятную ошибку.

# 18. Совместимость типов

Нельзя автоматически смешивать число и текст.

Например:

10 + "20"

является ошибкой.

Число 10 и текст "10" являются разными значениями.

# 19. Значение пусто

пусто означает отсутствие значения.

Пустой список [] и значение пусто являются разными значениями.

# 20. Дополнительные ключевые слова

добавить — добавляет значение в список.

удалить — удаляет элемент списка.

# 22. Грамматика языка

имя начинается с буквы.

После первого символа разрешены:

- буквы;
- цифры;
- символ _.

Имя не может совпадать с ключевым словом.

# 27. Система ошибок языка «Улитка»

Все ошибки языка должны сообщаться на русском языке.

Каждая ошибка по возможности содержит:

- код ошибки;
- номер строки;
- позицию;
- описание;
- ожидаемое значение;
- полученное значение;
- фрагмент исходной программы;
- указатель на место ошибки;
- рекомендацию по исправлению, если она возможна.

# 28. Категории ошибок

СИН — ошибки синтаксиса.

ИМЯ — ошибки имён.

ПЕР — ошибки переменных.

ТИП — ошибки типов.

СП — ошибки списков.

ФУН — ошибки функций.

БЛК — ошибки блоков.

ЗНА — ошибки значений.

# 30. Принцип работы с ошибками

Компилятор должен сообщать об ошибках понятным русским языком.

Компилятор не должен молча исправлять исходную программу.

Если возможно, компилятор должен предложить исправление.

Компилятор должен стараться обнаружить несколько ошибок за один запуск.

Если дальнейший анализ программы становится ненадёжным,
компилятор может прекратить проверку.

# 31. Ошибки синтаксиса

СИН-001 — отсутствует обязательная часть конструкции.

СИН-002 — неизвестное слово.

СИН-003 — незакрытая скобка.

СИН-004 — неправильное расположение оператора.

# 32. Ошибки имён

ИМЯ-001 — недопустимое имя.

ИМЯ-002 — имя совпадает с ключевым словом.

# 33. Ошибки переменных

ПЕР-001 — переменная не существует.

ПЕР-002 — переменная уже существует.

# 34. Ошибки типов

ТИП-001 — несовместимые типы.

ТИП-002 — недопустимая операция для данного типа.

# 35. Ошибки списков

СП-001 — индекс находится за пределами списка.

СП-002 — недопустимая операция со списком.

# 36. Ошибки функций

ФУН-001 — неправильное количество аргументов.

ФУН-002 — функция не существует.

ФУН-003 — неправильное использование функции.

# 37. Ошибки блоков

БЛК-001 — незавершённый блок.

БЛК-002 — лишнее слово «конец».

# 38. Ошибки значений

ЗНА-001 — неправильная запись числа.

ЗНА-002 — незакрытый текст.

# 41. Принцип разделения

Компилятор не должен состоять из одного большого модуля.

Каждый этап должен иметь отдельную ответственность.

# 42. Исходный язык

Исходным языком компилятора является язык программирования «Улитка».

Пользователь пишет программы на языке «Улитка».

# 43. Целевая платформа первой версии

Первой целевой платформой является браузер.

Для браузера компилятор создаёт:

HTML
CSS
JavaScript

# 44. Промежуточное представление

Между языком «Улитка» и целевым кодом используется промежуточное представление программы.

ППП является внутренним представлением программы.

Оно позволяет отделить язык «Улитка» от конкретной целевой платформы.

# 45. Обработка ошибок

Если обнаружена критическая ошибка исходной программы,
генерация целевого кода не выполняется.

Компилятор сообщает ошибку пользователю на русском языке.

# 46. Независимость генераторов

Генераторы HTML, CSS и JavaScript являются отдельными частями компилятора.

В будущем могут быть добавлены другие генераторы.

# 49. Принцип разделения ответственности

Каждый модуль выполняет только свою задачу.

Модуль чтения отвечает за чтение.

Распознаватель отвечает за распознавание элементов.

Синтаксический разбор отвечает за структуру.

Дерево представляет структуру программы.

Проверка смысла отвечает за семантическую правильность.

ППП представляет программу во внутреннем формате.

Генераторы создают целевой код.

Сборщик формирует готовый проект.

Система ошибок формирует сообщения об ошибках.

Оркестратор управляет последовательностью компиляции.

Журнал хранит сведения о ходе компиляции.

# 50. Правило ошибок

При критической ошибке дальнейшие этапы компиляции не выполняются.

Генерация HTML, CSS и JavaScript выполняется только после успешной проверки программы.

# 51. Расширяемость

Архитектура должна позволять добавлять новые возможности языка и новые целевые платформы без полного переписывания существующего компилятора.

Промежуточное представление отделяет язык «Улитка» от конкретной целевой платформы.

ППП — промежуточное представление программы.

ППП отделяет язык «Улитка» от целевой платформы.

Результатом компиляции является готовый проект, состоящий из необходимых файлов HTML, CSS и JavaScript.

# 64. Передача данных

Каждый модуль получает определённый входной формат и создаёт определённый выходной результат.

Модули не должны хаотично изменять результаты других модулей.

# 65. Версия языка

Первая версия языка:

Улитка 0.1

Архитектура должна учитывать возможность появления будущих версий языка.

# 66. Система ошибок

Ошибки всех этапов должны передаваться через единую систему ошибок.

Сообщения для пользователя формируются на русском языке.

2 + 3 * 4
2 + (3 * 4)
(2 + 3) * 4
